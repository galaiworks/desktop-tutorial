# NUMEN 公開前チェックリスト（監修・運営者向け）

実装はすべて完了しています。ここに挙げた項目は**人の判断が必要なもの**だけです。
`npm run validate` を実行すると、この一覧の未完了分が機械的にチェックされます。

```bash
npm run validate           # 未完了項目を一覧表示
npm run validate -- --strict   # 警告もエラー扱い（CIに載せる場合）
```

---

## A. 公開に必須（これが埋まらないと公開できません）

### A-1. 運営者情報

**ファイル：** `config/site.json`

```json
{
  "operatorName": "（例）NUMEN運営事務局 / 屋号 / 法人名",
  "contactEmail": "（例）support@example.com",
  "lastUpdated": "2026-08-05"
}
```

未設定のままだと、プライバシーポリシーと利用規約のページに
**「【公開前に要記載】」と赤字で表示されます**（黙って空欄にはなりません）。
特定商取引法・個人情報保護法の観点から、有料商品を扱う前に必ず埋めてください。

## B. 監修で品質が決まるもの（公開はできますが、埋めるほど良くなります）

### B-1. 各ナンバーの解説文（12種）

**ファイル：** `data/numbers/1.json` 〜 `33.json`

現在は**こちらで執筆したドラフト**が入っています。既存のブランド流派の文言は
一切転用していないため、権利上の問題はありませんが、監修者の言葉に置き換えると
サービスの独自性が上がります。

各ファイルの構造：

| 項目 | 内容 | 使われる場所 |
|---|---|---|
| `keywords` | 3語程度 | 結果画面のチップ |
| `essence` | 本質・性格 | フル鑑定・AI生成の素材 |
| `strengths` | 強み・才能（配列） | フル鑑定 |
| `mission` | 使命・人生テーマ | フル鑑定 |
| `love` | 恋愛傾向 | 恋愛レンズ |
| `work` | 仕事・適職傾向 | ビジネスレンズ |
| `caution` | 注意点 | フル鑑定 |

書き換えたら `disclaimer` から「ドラフト」の語を消してください（検証ツールの警告が消えます）。

### B-2. 数秘の流派設定

**ファイル：** `config/numerology.json`

| 設定 | 現在値 | 選択肢 |
|---|---|---|
| `masterNumbers.include33` | `true`（33を含む＝12種） | 含めない流派なら `false` |
| `masterNumbers.include44` | `false` | 使う流派なら `true` |
| `reductionMethod` | `"sum-all"`（全桁一括合計） | `"reduce-each-pillar"`（年・月・日を各々還元） |

**注意：** ここを変えると全ユーザーの診断結果が変わります。公開後の変更は避けてください。

### B-3. 相性マトリクス

**ファイル：** `config/numerology_affinity.json`

12×12＝144通り × 恋愛/ビジネスの2面。現在はこちらのヒューリスティクスによる
初期値です。監修者の解釈で 0〜100 の数値を上書きしてください。
一部だけの修正でも構いません（未設定は検証ツールがエラーとして検出します）。

**ファイル：** `config/big5_compat.json` — 性格面の相性の重み付け。
`similarity`（似ているほど加点）と `complementarity`（違うほど加点）を因子ごとに設定できます。

### B-4. 年運の解説（1〜9）

**ファイル：** `data/personal_year.json` — B-1と同様、ドラフトが入っています。

## C. 判断が必要な論点（要件定義書 §14）

### C-1. ビッグファイブ尺度をどちらにするか ★重要

**ファイル：** `config/big5_scale.json`

現在は **`numen-10`（独自尺度）** が有効です。

| | numen-10（現在） | tipi-j |
|---|---|---|
| 権利処理 | **不要**（自作） | 権利元の使用規定の確認が必要 |
| 学術的検証 | **未実施** | 済（902名・再検査信頼性 r=.64〜.86） |
| いま公開できるか | **できる** | できない（項目文が仮のまま） |

**独自尺度を既定にした理由：** 権利が未確認の尺度を載せたまま公開するリスクを避けるためです。
そのままリリースできます。

**TIPI-Jに切り替える場合の手順：**
1. 権利元に商用利用の可否・条件を確認する
2. `config/scales/tipi-j.json` の `items[].text` を正規の項目文に差し替え、`placeholder` を削除する
3. `config/big5_scale.json` の `active` を `"tipi-j"` に変更する
4. `npm run validate` でエラーが出ないことを確認する

※ 仮の項目文が残ったまま `active` にすると、検証ツールとユニットテストの両方が失敗します（事故防止）。

**訴求上の注意：** 独自尺度のあいだは「学術的に検証済み」と表示できません。
利用規約ページはこれを自動で出し分けています（設定を変えれば表記も変わります）。

### C-2. その他の未確定論点

| 論点 | 現在の実装 | 変更方法 |
|---|---|---|

## D. 環境変数（デプロイ時）

| 変数 | 未設定時の挙動 |
|---|---|
| `NEXT_PUBLIC_LINE_ADD_URL` | LINE導線が無効表示になる（**実質必須**） |
| `ANTHROPIC_API_KEY` | AI生成せず、決定論テンプレの診断文になる |
| `SUPABASE_URL` / `SUPABASE_SERVICE_ROLE_KEY` | 保存とマッチングが無効（診断は動く） |
| `NEXT_PUBLIC_LIFF_ID` | `/liff` がフル鑑定を表示しない |

Supabaseを使う場合は `supabase/migrations/` のSQLを順に適用してください。
